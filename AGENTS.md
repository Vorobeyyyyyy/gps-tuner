# AGENTS.md — GPS Tuner

Android-приложение для настройки USB GPS-приёмников u-blox **без root**: читает и меняет настройки по протоколу UBX, показывает живой статус.
- Требования и обоснования решений — [ТРЕБОВАНИЯ.md](ТРЕБОВАНИЯ.md).
- Как пользоваться — [README.md](README.md).

---

## Сборка и тесты

| | |
|---|---|
| Язык и UI | Kotlin 2.0.20, Jetpack Compose (BOM 2024.09.03, Material 3) |
| Сборка | AGP 8.5.2, Gradle 8.9 (wrapper) |
| SDK | compileSdk 34, minSdk 28 (Android 9), targetSdk 34 |
| USB | `com.github.mik3y:usb-serial-for-android:3.8.1`. JitPack подключён только для группы `com.github.mik3y` |

**Нужен JDK 17.** На более новых JDK Gradle 8.9 / AGP 8.5 не запускаются. Укажите `JAVA_HOME`. Путь к SDK — в `local.properties` (`sdk.dir`), файл в `.gitignore`.

```
./gradlew testDebugUnitTest    # JVM-тесты
./gradlew assembleRelease      # app/build/outputs/apk/release/app-release.apk
```
Release собирается с R8. `proguard-rules.pro` держит драйверы usb-serial: они создаются через рефлексию.

**Версии и релизы.** Каждый push в `main` → `.github/workflows/release.yml`: тесты, APK, тег и GitHub Release `v<appVersion>.<N>` с `GpsTuner-<версия>.apk`.
- N = `git rev-list --count HEAD`, передаётся как `-PversionCode` и идёт в `versionCode`. Без него `versionCode = 1`. Историю `main` не переписывать: число коммитов не должно уменьшаться.
- `appVersion` (сейчас `1.0`) — в `gradle.properties`, меняется вручную.
- Подпись: если задан `RELEASE_KEYSTORE_FILE` (+ `RELEASE_KEYSTORE_PASSWORD`, alias `gps-tuner`), то release-ключом, иначе debug-ключом. В CI ключ берётся из секретов `RELEASE_KEYSTORE_BASE64` и `RELEASE_KEYSTORE_PASSWORD`. Локально — `~/.android/gps-tuner-release.env` и `.jks` рядом.
- Чтобы коммит не выпускал релиз, добавьте `[skip ci]` в сообщение коммита.

## Устройство

Код в `app/src/main/java/ru/gpstuner/`.

| Файл | Что внутри |
|---|---|
| `ubx/Ubx.kt` | Константы классов/ID, сборка кадра, Fletcher-8, `UbxMessage` (чтение LE-полей) |
| `ubx/StreamParser.kt` | Делит поток на UBX-кадры и NMEA-строки; кадры могут приходить кусками, мусор отбрасывается |
| `ubx/Nmea.kt` | Контрольная сумма, сборка строк, разбор RMC/GGA |
| `ubx/Messages.kt` | CFG-RATE, CFG-NAV5, CFG-GNSS, CFG-MSG, CFG-PRT, CFG-CFG, MON-VER, NAV-PVT, NAV-SAT. Пределы частоты M8 (`ReceiverInfo.maxRateHz`) |
| `ubx/UbxClient.kt` | Запрос-ответ поверх транспорта |
| `transport/GpsTransport.kt` | Интерфейс канала: `msgPort` (1 — UART за мостом, 3 — USB), `baud`/`setBaud` только для мостов |
| `transport/UsbTransport.kt` | Поиск адаптеров (u-blox `1546` + мосты), запрос разрешения USB, открытие, автоподбор скорости для мостов |
| `transport/DemoTransport.kt` | Эмулятор u-blox M8 (NEO-M8N, прошивка во flash); `bridge = true` — мост с буфером UART и потерями |
| `ReceiverSession.kt` | Чтение настроек, черновик, пресеты, «Применить», «Сохранить», сброс, разгрузка порта, живой статус |
| `AppViewModel.kt` | Список адаптеров, подключение и отключение, USB-события |
| `ui/` | `ConnectScreen`, `ReceiverScreen`, `Components`, `AppRoot`; `theme/Theme.kt` — цвета, типографика, масштаб |

**Демо-режим.** `MainActivity` понимает extras `demo` и `demo_bridge` (boolean): сразу подключиться к эмулятору приёмника. Эмулятор стартует на 10 Гц и с перегрузкой: так видны предупреждения.

## Инварианты — не ломать

### Протокол
- **Байты кадров зафиксированы тестами** (`FrameTest`): 1 Гц, Automotive, сохранение, сброс, CFG-MSG. Меняете кодирование — сверяйте с тестами.
- **`UbxClient` шлёт запросы строго по одному** (Mutex). `poll` считает ACK-NAK ответом «не поддерживается» и возвращает `null`. `command` ждёт ACK/NAK, при тишине повторяет.
- **Смена скорости порта (CFG-PRT):**
  - отправить на старой скорости;
  - через 150 мс переключить ГУ (`afterSend`): ACK приходит уже на новой скорости;
  - если ACK нет — проверить связь опросом, иначе вернуть старую скорость.
- **Порядок в «Применить»:** частота → модель → системы → NMEA → **скорость порта последней**. После применения настройки всегда перечитываются из приёмника.
- **CFG-NAV5 меняет только dynModel** (mask = 0x0001).
- **CFG-GNSS** — read-modify-write всех блоков. При включении системы ставится sigCfgMask (L1), если он пустой.
- **CFG-MSG** — короткая форма (3 байта): действует на текущий порт.
- **Сброс** — CFG-CFG: clear + load всех разделов во всех видах памяти. Для мостов после сброса скорость ГУ возвращается на 9600.

### Ограничения M8 и пределы частоты
- **Системы:**
  - ГЛОНАСС и BeiDou одновременно не работают — включение одной выключает другую;
  - GPS выключить нельзя.
- **Пределы частоты** (`maxRateHz`):

  | Прошивка | 1 система | 2 системы | с Galileo |
  |---|---|---|---|
  | flash («EXT CORE») | 10 Гц | 5 Гц | 3 Гц |
  | ROM («ROM CORE») | 18 Гц | 10 Гц | 10 Гц |

  Неизвестную прошивку считаем как flash.
- **M9/M10 не поддерживаются** (у них CFG-VALSET) — показываем «не поддерживается», ничего не шлём.

### Пресеты (`Preset` в `ReceiverSession.kt`)
| Пресет | Частота | Системы |
|---|---|---|
| «Навигатор» | 1 Гц | GPS + ГЛОНАСС + Galileo + SBAS + QZSS |
| «Быстрый» | 5 Гц | GPS + ГЛОНАСС + SBAS + QZSS |

- Оба: модель «Автомобиль», **NMEA только RMC и GGA**.
- **Скорость порта пресеты не трогают:** её смена требует той же скорости в USB GPS.
- Почему только RMC и GGA: UsbGps4Droid (`org.broeuschmeul.android.gps.usb.provider`) строит координаты только из них — проверено по его `NmeaParser.java`. «Точность» для Android он считает как HDOP × 10.

### Адаптеры с мостом (`isBridge`, `msgPort == 1`)
- **Строка «Порт» только у мостов.** У родного USB u-blox скорость ни на что не влияет.
- **Загрузка порта считается только по байтам NMEA** (`nmeaBytesReceived`) — это то, что получит USB GPS. Собственные UBX-опросы не в счёт. NAV-SAT на мосту опрашивается раз в 3 с.
- **Перегрузка (> 90%) при подключении** → вместо чтения настроек карточка `overloadGate`:
  - «Разгрузить порт» — 1 Гц + RMC/GGA, команды уходят до чтения настроек;
  - «Поднять до 115200»;
  - «Прочитать как есть».

### Сосуществование с USB GPS
- **В манифесте намеренно нет `USB_DEVICE_ATTACHED`:** не перехватываем автозапуск UsbGps4Droid.
- Адаптер доступен одному приложению. Конфликт виден только при `port.open` → `BusyException` → «Адаптер занят USB GPS».
- **После отключения** — напоминание запустить USB GPS. Если скорость порта менялась — с этой скоростью.

### Потоки
- **Состояние сессии живёт в главном потоке:** корутины сессии запускаются в `viewModelScope`. Колбэки транспорта приходят из фонового потока; запись в транспорт — `Dispatchers.IO`.
- **В тестах сессии** — однопоточный диспетчер (см. `ReceiverSessionTest`).

## UI-соглашения
- **Строки на русском прямо в коде**, без `strings.xml`. Комментарии тоже на русском, редкие — только где неочевидно.
- **Компактная шкала:**
  - кнопки `TouchHeight` = 44 dp, варианты `PillHeight` = 40 dp;
  - шрифты задаёт `Theme.kt`, без межбуквенной разрядки.
- **Без прокрутки.** Основной экран должен влезать в ≈1210×456 dp. Стартовый экран — тоже.
- **Масштаб.** `ScaledForScreen` увеличивает плотность, пока окно не сожмётся до этой площади (масштаб 1…1,6).
  - **Диалоги и всплывающие меню** рисуются в своих окнах с системной плотностью — их содержимое оборачивать в `ScaledForScreen`.
  - Поэтому вместо `AlertDialog` используется свой `Dialog`.
- **Изменения в черновике показываются кнопками, а не текстом:**
  - `Pill(pending = true)` — пунктир, заливка — каким значение станет;
  - точка у подписи строки;
  - счётчик на «Применить» (`pendingChanges`).
  - Пунктир рисуется **внутри** Surface: снаружи Material3 расширяет зону нажатия до 48 dp.
- **Подсказки.** Постоянных нет, только предупреждения (`Hint` с `Level.WARN/BAD`). Исключение — строка NMEA, там INFO про лишний трафик.
- **Форматирование:** NMEA и протокол — только `Locale.US`; UI — `Locale.getDefault()`.

## Известные пробелы
- **u-blox 7 — частично:**
  - одновременно только одна система (GPS или ГЛОНАСС), а правила в UI — от M8, поэтому пресет упрётся в NAK на CFG-GNSS;
  - нет NAV-SAT (нужен NAV-SVINFO), график спутников пуст;
  - подписи пределов частоты говорят «M8».
- **u-blox 6** — нет CFG-GNSS и NAV-PVT.
- **Не проверено на реальном железе:**
  - смена скорости на настоящих мостах CH340/CP210x;
  - автоподбор скорости;
  - адаптеры без flash и батарейки: ACK на сохранение приходит, а настройки пропадают после выключения, приложение этого не видит.
